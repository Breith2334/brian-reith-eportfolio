Software Design and Engineering: Travlr Getaways

Artifact Code

  • Original artifact (before enhancement)
  • Enhanced artifact (API error handling)

1. About the Artifact

The artifact I chose is the Travlr Getaways full-stack web application, which I built during my coursework to demonstrate my understanding of full-stack development and how the layers of a web application work together.

The application uses Express and Node.js on the backend and Angular for the admin interface. Visitors can view travel information, and administrators can manage trip listings. The project includes API routes, database interactions, and a functional UI for managing content.

2. Why I Included It

Travlr Getaways is one of the best examples of my ability to work across the full stack and use multiple technologies in a single project. It highlights my experience with JavaScript, Express, Angular, API development, and MongoDB.

For this milestone, I improved the application's API error handling. The enhancement makes error responses more consistent and easier to understand, which improves both maintainability and the user experience. The artifact shows that I can work with an existing codebase, understand its structure, and make targeted improvements without rewriting the entire application.

3. Course Outcomes

This enhancement moved me toward the outcome of using well-founded techniques, skills, and tools to build software solutions that provide real value. I reviewed the existing code, identified a weakness in the error-handling logic, and implemented a clean, maintainable improvement. I also strengthened my professional communication by documenting the changes and explaining why they were necessary.

My next step is to review instructor feedback and make any adjustments needed before publishing the final version.

4. Reflection on the Process

Enhancing Travlr Getaways gave me a better appreciation for maintaining and improving existing software. I learned that meaningful improvements don't always require building something new. Small, focused changes can make a big difference in reliability and user experience. I also gained more experience reading and understanding how the parts of a full-stack application connect.

One challenge was figuring out where to make changes without breaking existing functionality. I had to carefully review the routes, controllers, and error-handling flow so that my enhancement fit naturally into the application. The process made me more comfortable working inside an existing codebase and reinforced the importance of testing changes thoroughly before considering an enhancement complete.
